# iw3 GUI Settings Reference

A complete reference for every setting in the iw3 GUI (`iw3-gui.bat`): what it does, its choices/range/default, and a recommendation. This mirrors the tooltips shown when you hover over each control in the app, with extra detail and practical recommendations added.

---

## File Options (top bar, above the main panels)

| Setting | Type / Choices / Default | What it does | Recommendation |
|---|---|---|---|
| **Resume** | Checkbox, default **On** | Skip processing when the output file already exists. | Leave on for batch jobs so re-runs don't redo finished files. Auto-disabled (greyed out) for single video files — see [Auto Resume](#auto-resume) instead for that case. |
| **Process all subfolders** | Checkbox, default Off | When the input is a folder, also process videos/images inside its subfolders, not just the top level. | On if you organize your movies into subfolders. |
| **Skip Error** | Checkbox, default Off | Skip videos that cause errors during batch processing, and those that previously encountered errors. | On for unattended batch jobs over many files. |
| **EXIF Transpose** | Checkbox, default **On** | Transpose images according to their EXIF Orientation Tag (so sideways phone photos display upright). | Leave on. |
| **Add metadata to filename** | Checkbox, default Off | Encodes your current settings (model, 3D strength, convergence, etc.) into the output filename, so you can tell which settings made which file later, and so Auto Resume can find a matching in-progress job. | On — this is what makes Auto Resume reliable and lets you compare settings later from the filename alone. |
| **Image Format** | ComboBox: `png` / `jpeg` / `webp`, default `png` | The file format used for image (not video) output. | `png` for lossless quality; `jpeg`/`webp` for smaller files at some quality cost. |

## Stereo Generation

### Core 3D effect

| Setting | Type / Choices / Default | What it does | Recommendation |
|---|---|---|---|
| **3D Strength** (Divergence) | EditableComboBox: `5.0/4.0/3.0/2.5/2.0/1.0`, default `2.0` | The master strength of the whole 3D effect — how far things shift between the left/right eye. | **2.0–3.0** for most movies. Higher = more dramatic depth but more edge artifacts; lower = subtler, cleaner. |
| **Convergence Plane** (mode) | ComboBox: `constant` / `sod_v1` / `face_detect`, default `constant` | How the "screen depth" (the point that looks like it's exactly at the screen surface) is chosen. `constant`: fixed position you set manually. `sod_v1`: AI auto-picks a focus point based on the most visually important subject. `face_detect`: auto-centers on detected faces, ignoring the value box. | `constant` for predictable results; `sod_v1` for movies with a clear subject and varying depth. Pair either auto mode with **Scene Boundary Detection**. |
| **Convergence Plane** (value) | EditableComboBox: `0.0/0.25/0.5/1.0`, default `0.25` | Where the "screen depth" sits, from 0 (everything pops toward you) to 1 (everything sits behind the screen). Only used directly in `constant` mode — in `sod_v1` it acts as a relative offset within the detected subject's depth range. | `0.5` as a balanced starting point. |
| **Convergence Smoothing** | EditableComboBox: `0.95/0.9/0.75/0.5/0.25/0`, default `0.9` | Only affects `sod_v1`/`face_detect` modes. Controls how quickly the automatic convergence point reacts to scene changes. Higher = smoother but slower; lower = more reactive but jitterier. `0` = no smoothing. | `0.75` for slow/calm films, `0.5` for action, `0.6` for general/comedy pacing. See [Genre Recommendations](#genre-based-recommendations). |
| **Your Own Size** (IPD Offset) | SpinCtrl, range `-10..20`, default `0` | Fine-tunes the 3D effect for your own eye spacing (interpupillary distance). | Leave at `0` unless you have a specific reason to widen/narrow the simulated eye distance. |
| **Synthetic View** | ComboBox: `both` / `right` / `left`, default `both` | Which eye view gets newly generated by AI. `both` synthesizes both eyes from the original center image. `right`/`left` keep the original image as one eye unchanged and only synthesize the other. | `both` — most natural. `right`/`left` is faster but can look slightly less balanced. |
| **Method** | ComboBox: `mlbw_l2` / `mlbw_l4` / `mlbw_l2s` / `mlbw_l2_inpaint` / `row_flow_v3` / `row_flow_v3_sym` / `row_flow_v2` / `forward_fill` / `forward_inpaint` / `monobw` / `monobw_inpaint`, default `mlbw_l2s` | How the second eye view is generated from the depth map. `row_flow_v3`/`row_flow_v3_sym`: fast, AI-based, solid all-rounder. `mlbw_l2`/`mlbw_l4`: more advanced layered AI warping, supports stronger 3D strength. `*_inpaint` variants additionally fill in hidden areas behind objects instead of stretching/smearing them — slower, cleaner edges. `forward_fill`/`monobw`/`grid_sample`/`backward`: older, simpler, non-AI methods, mainly for testing/speed. | `mlbw_l2_inpaint` or `forward_inpaint` for best quality; `row_flow_v3_sym` for speed. |
| **Inpainting Model** | ComboBox, choices from your configured inpaint models (e.g. `light_inpaint_v1`, `Video_Large_Aether`, `Video_Medium_Aether`, `Video_Medium_Aether_v2`) — only shown for `*_inpaint` methods | Which AI model fills in the hidden areas behind objects. Larger/"Large" models give cleaner results but are slower. | `light_inpaint_v1` (default) is fast; `Video_Large_Aether` for the best quality if you can spare the time. |
| **Inpaint Overlap Frames** (Pre/Post) | EditableComboBox each: `0/3`, default `3` | How many extra frames before/after each processed chunk are fed to the inpainting model for context, keeping filled-in areas consistent frame to frame. | Default (`3`/`3`) for smoothness; lower for speed if needed. |
| **Inpaint Mask Dilation** (Inner/Outer) | EditableComboBox each: `0/1/2`, default `0`/`0` | **Inner**: grows the "needs filling in" area inward (shrinks the foreground edge slightly for smoother blending). **Outer**: grows it outward into the background, giving the inpainting model more room. | `0`/`0` normally; raise **Inner** if you see a thin halo around foreground objects, raise **Outer** if you still see smearing right behind them. |
| **Inpaint Max Width** | EditableComboBox: `""/1920`, default blank | Caps the resolution the inpainting model processes at, to save VRAM/time on large videos. | Leave blank for best quality; set `1920` only if you run out of memory. |
| **Stereo Processing Width** | EditableComboBox: `Default/1920/1280/640`, default `Default` | Only used for `row_flow_v3`/`row_flow_v2`. Resizes the image to this width before generating the 3D effect (separate from output resolution). | `Default` (source size) unless you need to trade quality for speed. |

### Depth estimation

| Setting | Type / Choices / Default | What it does | Recommendation |
|---|---|---|---|
| **Depth Model** | ComboBox, long list (see below), default index 3 | Which AI model estimates depth from the image. | See [Depth Model Guide](#depth-model-guide) below. |
| **Depth Resolution** | EditableComboBox: `Default/512`, default `Default` (≈392) | How much detail the depth model works with internally (its short-side resolution in pixels). Higher = finer depth detail but more VRAM/time — cost grows roughly with the *square* of the resolution. | `Default` for most content; `448–512` if you have VRAM to spare and want finer detail. |
| **Limit to source** | Checkbox | Safety cap: if your typed Depth Resolution is *higher* than the source video's own resolution, this brings it back down to match the source. Never raises a lower value up. | On. |
| **Foreground Scale** | EditableComboBox: `-3..3`, default `0` | Reshapes the depth curve for the *whole* image (foreground AND background). | `0` unless you specifically want to reshape overall depth; different from Foreground Pop. |
| **Depth Anti-aliasing** | Checkbox, default Off (only enabled for certain depth models) | Smooths small jagged/staircase artifacts in the depth map using a dedicated AI model, without changing depth values much. | On when available — minor cost, cleaner result. |
| **Foreground Pop** | EditableComboBox: `0.0/0.25/0.5/0.75/1.0`, default `0.0` | Pushes only the *nearest* pixels further toward the audience; background untouched. Different from Foreground Scale. | `0.0` (off) by default; raise for stronger "pop" on foreground subjects only. |
| **Edge Fix** (X / Y) | EditableComboBox X: `0/1/2/3/4` default `2`; Y: `""/0/1/2` default `1` | Reduces distortion/bleeding/smearing at foreground-background edges. | Default (`2`/`1`); raise if you still see edge smearing, lower if it looks artificial/blobby. |

### Flicker reduction & scene detection

| Setting | Type / Choices / Default | What it does | Recommendation |
|---|---|---|---|
| **Flicker Reduction** (EMA Normalize) | Checkbox (Video only, experimental) | Smooths the depth map over time so it doesn't flicker/wobble between frames. | On for most videos, paired with Scene Boundary Detection. |
| **Decay Rate** | EditableComboBox: `0.99/0.95/0.9/0.75/0.5/0`, default `0.9` | How much the depth map is smoothed frame to frame. Higher = smoother but slower to react; lower = reacts faster but may flicker more. `0` = no smoothing. | See [Genre Recommendations](#genre-based-recommendations). |
| **Lookahead Buffer Size** (EMA Buffer) | EditableComboBox: `150/60/30/1`, default `30` | How many frames are looked at together to judge the near/far depth range. Bigger = more stable but slower to adapt *within* a shot. Scene Boundary Detection resets this at every real cut regardless. | See [Genre Recommendations](#genre-based-recommendations). |
| **Scene Boundary Detection** | Checkbox, default Off | Detects real scene/shot cuts and resets the depth model and Flicker Reduction exactly there, instead of letting smoothing bleed across unrelated scenes. Also makes [Auto Resume](#auto-resume) align cleanly. | On for movies/TV, especially with Flicker Reduction or Auto Resume. |
| **Use scene boundary cache** | Checkbox, default **On** | Saves detected scene cuts to disk so re-running the same video doesn't need to re-scan every time. | On. |

| Setting | Type / Choices / Default | What it does | Recommendation |
|---|---|---|---|
| **Preserve Screen Border** | Checkbox, default Off | Forces the very edges of the frame to zero 3D shift, preventing odd cutoffs at left/right edges. | On if you notice distracting edge artifacts; off for maximum 3D strength everywhere. |
| **Stereo Format** | ComboBox: `Full SBS` / `Half SBS` / `Full TB` / `Half TB` / `VR90` / `Cross Eyed` / `RGB-D` / `Half RGB-D` / `Anaglyph` / `Export` / `Export disparity` / `Debug Depth`, default `Full SBS` | The final output layout. Full SBS/TB keep both eyes at full resolution (bigger file); Half squeezes both into the original frame size (smaller, more broadly compatible). VR90 is for VR headsets. Cross Eyed needs no equipment. Anaglyph is red/cyan glasses. RGB-D/Export save raw depth data instead of a finished 3D image. | `Half SBS` for most TVs and 3D players, unless you specifically need another format. |
| **Anaglyph Method** | ComboBox (only shown for Anaglyph format): `dubois/dubois2/color/gray/half-color/wimmer/wimmer2`, default `dubois` | The color-filtering recipe for red/cyan glasses viewing. | `dubois2` — most natural, least color distortion. `gray` if you want zero color distortion but accept losing color. |
| **Depth Only** (export) | Checkbox (only shown for Export modes) | Exports depth images only. Exported data with this option cannot be re-imported. | Off unless you specifically only need depth maps. |
| **Resize to fit** (export) | Checkbox (only shown for Export modes) | Resizes depth images to match RGB image size. Can make the process much slower / output much larger. | Off unless your downstream workflow requires matched sizes. |

|---|---|---|---|
| **Device** | ComboBox, built from detected GPUs (+ "All CUDA Device" if multiple) / CPU | Which GPU (or CPU) does the AI processing. | Your GPU. "All CUDA Device" if you have multiple GPUs. CPU only if you have no compatible graphics card (much slower). |

| **torch.compile** | Checkbox, default Off | Optimizes the AI model before running — slower startup (must compile after any settings change) for faster processing afterward. ## Depth Model Guide

| Family | Examples | Best for | Notes |
|---|---|---|---|
| **VDA_\*** (Video Depth Anything) | `VDA_S/B/L`, `VDA_Metric_*`, `VDA_Stream_*`, `VDA_Stream_Metric_*` | **Video** | Built specifically to keep depth stable/flicker-free across frames. `_Stream_` variants are the newer streaming-capable versions. `_Metric_` variants estimate real-world distances. |
| **Any_V2_\*** | `Any_V2_S/B/L`, `Any_V2_N_*`, `Any_V2_K_*` | Single images | Depth Anything V2 generation — sharp on stills, can flicker on video. |
| **Any_V3_Mono\*** | `Any_V3_Mono`, `Any_V3_Mono_01` | Single images | Newest (V3) generation — generally the sharpest for stills, but no video-specific (flicker-resistant) variant exists yet. |
| **Distill_Any_\*** | `Distill_Any_S/B/L` | Single images | Distillation-based, separate project from Depth Anything. |
| **ZoeD_\*** / **DepthPro** | `ZoeD_N/K/NK`, `ZoeD_Any_N/K`, `DepthPro`, `DepthPro_S` | Older / specialized use | Earlier-generation models, generally superseded by the above for most uses. |

**Rule of thumb:** for video, use a `VDA_*` model (flicker resistance matters more than raw sharpness). For a single photo, `Any_V3_Mono` is typically the sharpest choice.

## Genre-Based Recommendations

Practical EMA Decay Rate / EMA Buffer / Convergence Smoothing combinations, based on a film's pacing and cut frequency:

| Setting | Slow / contemplative (e.g. *Interstellar*) | Moderate / comedic (e.g. *Joe's Apartment*) | Fast-cut action (e.g. *Mortal Kombat II*) |
|---|---|---|---|
| **EMA Decay Rate** | `0.95` | `0.85` | `0.75` |
| **EMA Buffer** | `60` | `30` (default) | `15` |
| **Convergence Smoothing** | `0.75` | `0.6` | `0.5` |

Always pair these with **Scene Boundary Detection** so the smoothing resets cleanly at real cuts instead of drifting across them, and with **Auto Resume** for anything long enough to risk an interruption.

## NVENC Bit-Depth Limits

Verified directly on an RTX 5090: **NVENC hardware encoders (`h264_nvenc`/`hevc_nvenc`) cannot truly encode beyond 10-bit precision**, on any GPU generation including current ones — there is no real 12-bit hardware encode mode. The program automatically caps **Bit Depth Upgrade** down to 10 on these codecs to avoid crashing. Feeding NVENC a 16-bit-shaped buffer (e.g. `p016le`) doesn't crash, but the actual encoded bitstream still only contains 10-bit precision — the extra bits are silently discarded by the hardware, not genuinely preserved.

**For genuine 12-bit output**, use a CPU encoder (`libx265`), which does support a real Main 12 profile.

---

## Pixel Format Guidance

For 3D conversion specifically (not just general video), the **chroma subsampling format matters more than bit depth**: the default `yuv420p` discards 3/4 of the color detail, which this project's README specifically calls out as a cause of red-color degradation and **left/right-eye crosstalk/ghosting**.

- **Recommended: `yuv444p`** — full color detail, no subsampling, works natively on NVENC without any translation tricks.
- For the best possible result (full color *and* genuine higher bit depth), switch to **`libx265`** and pair `yuv444p` with **Bit Depth Upgrade 10** — confirmed to produce a real `Main 4:4:4 10` profile stream, at the cost of much slower (CPU-based) encoding.
- On NVENC, combining `yuv444p` with a Bit Depth Upgrade has no valid hardware translation path and is automatically clamped back to 8-bit `yuv444p` to avoid crashing.

## Tune Notes

`uhq` (Ultra High Quality) is only available for `hevc_nvenc` (not `h264_nvenc`) and requires a relatively recent NVIDIA GPU. Verified directly: it works correctly with 8-bit and 10-bit pixel formats, giving a modest quality improvement over `hq` at a small speed cost. It is automatically unavailable in the Tune dropdown when using `h264_nvenc`, since that encoder doesn't support it.

## HDR/Dolby Vision Guidance

**Preserve Dolby Vision only helps if your actual playback display supports it.** Practical notes from real-world testing:

- **DLP projector + large screen (3D):** generally **not recommended**. Projectors are far dimmer than TVs even before factoring in 3D (active/passive 3D methods typically halve perceived brightness on top of that), so HDR/Dolby Vision's higher brightness expectations often get tone-mapped down so aggressively the result looks flatter than a well-graded SDR version. Most projectors also lack a Dolby Vision-certified chip, meaning the metadata gets ignored entirely.
- **VR headset:** also generally not worth it — most VR video players don't have an HDR/Dolby Vision-aware playback pipeline and just treat the video as a generic stream, ignoring the metadata regardless.
- **Dolby Vision-certified OLED/QLED TV:** this is the one case where Preserve Dolby Vision is clearly worth using.

**Recommendation:** test a plain SDR or HDR10 (non-Dolby-Vision) conversion on your actual display before committing the extra processing time to Dolby Vision preservation, unless you specifically know your display chain supports it end-to-end.

## Known Interactions & Gotchas

- **Resume vs. Auto Resume**: the "Resume" checkbox (top bar) is for batch/folder jobs and image-sequence exports — it's auto-disabled for single video files. Use **Auto Resume** (Video Filter group) for crash/interruption recovery on a single video.
- **Auto Resume + filename matching**: if resuming a job after closing the GUI, the output filename must match *exactly* (including all settings encoded into it) for the checkpoint to be found. Pointing Output directly at the exact existing filename (not just a folder) guarantees a match regardless of any other setting drift.
- **Auto Resume + Scene Boundary Detection**: Scene Boundary Detection continues working normally for the entire video after a resume point — it is not disabled by a crash. Only the exact resume point itself is an unavoidable, unaligned seam.
- **Worker Threads**: increasing this *and* Depth Batch Size together can sometimes be *slower*, not faster, because the GPU-bound depth/stereo computation is internally serialized (one batch at a time) — extra worker threads mostly end up idling with their batch already loaded into VRAM, waiting their turn. Prefer raising Depth Batch Size alone, with Worker Threads kept low (2).
